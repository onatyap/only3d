# Upstream projects

only3d writes its own engine in Rust, but it follows four open-source projects closely. It
takes data and behaviour from them, uses them as references to compare against, and treats
them as the source of truth for anything the printer itself checks. All four are AGPL-3.0, like only3d (AGPL-3.0-or-later). Copying their tables or porting
their code is allowed if their notices are kept and modified files are marked. Reimplementing
from the idea keeps a module ours. We prefer that for slicing algorithms.

`sh tools/fetch-upstream.sh` clones each of them at the pinned revision below into
`third_party/upstream/`. That folder is git-ignored. Generators read from it.

## Bambu Studio: the source of truth for what the printer reads

What we use today:
- **System presets and machine G-code templates.** Embedded in `profiles/bambu`; rendered by
  `only3d-profiles`. Our H2D start and end sequences are Bambu's own, line for line.
- **The G-code CONFIG block.** `only3d-profiles/src/gcode_config.rs`, generated by
  `only3d-profiles/tools/gen_bambu_options.py` from `PrintConfig.cpp`. It follows
  `GCode::append_full_config`: the full config, sorted, serialized by option type, with
  per-variant values reduced to the job's extruders (`update_values_to_printer_extruders`).
  The H2D checks its nozzles against this block (print_error 05FF_8053). For the test tile
  it matches the Bambu CLI with 619 of 619 keys equal.
- **Behaviour taken from `GCode.cpp`.** The machine envelope (`M204 T`), the first-layer
  probing area, wrapping detection only when enabled, and `filament_map` (`T` and `G151`
  use the right nozzle).
- **Nozzle codes.** `DevNozzleSystem.cpp`: `HS01` is H = nozzle, S = standard flow, 01 =
  hardened steel.
- **HMS texts.** Read from the installed app's `hms/hms_en_*.json`.
- **The CLI as an oracle.** `export_bambu_project {slice: true}` slices the same plate in
  Bambu Studio; comparing it with ours found both nozzle bugs.

## open-bamboo-networking: what Bambu Studio sends to a printer

This is an open reimplementation of Bambu's closed network plugin.

- **Print command.** Our LAN `project_file` command (`only3d-bambu/src/commands.rs`) matches the
  plugin's `start_local_print` field for field. The audit of 2026-11-15 found that Studio
  sends no nozzle data for an H2D LAN print. The remaining differences are harmless:
  - `md5` is `""`; the plugin sends `"from_sd_card"`.
  - `cfg` is missing.
  - `layer_inspect` defaults to false; Studio sends true.
- **Still to adopt:**
  - The port-6000 control channel for file listing (`LIST_INFO`, `SUB_FILE`).
  - eMMC printing (`brtc://emmc/...`).

## bambuddy: the printer commands and report fields we lack

Commands to add, most useful first (`backend/app/services/bambu_mqtt.py`):
1. **HMS recovery.** `ignore {err, param:"reserve", job_id}`, `idle_ignore`,
   `clean_print_error` and `system.uiop`. `hms_actions.json` says what each code offers.
   For example, 05FF_8053 offers "resume" or "ignore".
2. **`select_extruder {extruder_index}`.**
3. **AMS.** `ams_control`, `ams_get_rfid`, slot reset, and `ams_filament_drying`. Also fix our
   load/unload payloads to match bambuddy's:
   - AMS trays use `curr_temp`/`tar_temp` -1.
   - The external spools use `{255, 254, 254}` for left and `{255, 0, 255}` for right.
4. **Pressure advance.** `extrusion_cali_get`, `_sel`, `_set` and `_del`; the H2D form takes
   `extruder_id`/`nozzle_id`.
5. **Machine settings.** The `calibration` bitmask, `print_option` (auto recovery, sound,
   auto switch filament), `xcam_control_set`, `set_airduct`, and the chamber temperature
   (`M141`).

Report fields to parse:
- `device.extruder` state bits (target, switching, busy).
- `device.nozzle.info`: wear, `sn`, and the full flow-code table. S/A/X are standard,
  H/E high flow, U TPU high flow; T and B are also defined.
- The track-switch AMS (`info` extruder 0xE).
- `print.mapping`.
- The `stg[]` stage names.
- The door bit (`stat` bit 23) and the Developer Mode bit (`fun` bit 29).
- The `print_error` level: bits 12–15 give 0x4 stop, 0x8 pause, 0xC prompt.

## OrcaSlicer (and Bambu Studio's libslic3r): where the native slicer goes next

This is the ranked plan from the 2026-11-15 audit. It names the reference functions; we
reimplement from the idea.

1. **Overhang wall speed and fan.** Default-on in Bambu's H2D presets.
   References: `OverhangDetector.cpp`, `GCode.cpp` `get_overhang_degree_corr_speed`, and
   `CoolingBuffer.cpp`, which keeps overhangs out of the cooling slowdown.
2. **Elephant-foot compensation.** 0.15 mm on the first layer
   (`ElephantFootCompensation.cpp`).
3. **Time estimates.** Add the start-sequence time (`machine_prepare_compensation_time` and
   the stages flagged `prepare_stage`) and a look-ahead planner
   (`GCodeProcessor.cpp` `TimeMachine`). Expose it as an `estimate_gcode` tool.
4. **Monotonic top and bottom surfaces** (`FillRectilinear.cpp` `FillMonotonic*`).
5. **Seams.** Prefer concave corners, stay aligned across layers, avoid overhangs
   (`SeamPlacer.cpp`). Also fix the "nearest" seam, which measures from the bed origin
   instead of the nozzle.
6. **Gap fill and thin walls via the medial axis** (`MedialAxis.cpp`). Arachne comes later.
7. **Bridges.** Internal bridges over sparse infill, anchoring, and angle scoring
   (`BridgeDetector`, Orca `bridge_over_infill`).
8. **Scarf seams, then adaptive layer heights.**

Done:
- Tree supports, after Bambu Studio 2.09's default organic trees (`Support/TreeSupport3D.cpp`,
  `TreeSupportCommon.hpp`, `SupportCommon.cpp` `tree_supports_generate_paths`): overhang
  clusters as `TreeSupport::detect_overhangs`, roofs and tips at the top rate's density,
  Rahm's radii (tip, branch, 5° growth), slow and fast branch angles with the radius growth as
  extra speed, avoidance grown from the plate, resting on the model with a floor, 2.09's
  flared plate feet, hollow single-wall branches (two walls past ~150 mm²). Branches are
  nodes moved towards their nearest neighbour rather than influence areas, and drawn as
  circles rather than smoothed tubes. On the H2D presets (`tools/supports_verify.py`) a T,
  an arch, a hook, a sphere, a table, a torus, 3DBenchy and Bambu's FDM test come out at
  0.87–1.06× Bambu Studio 2.09's grams and 0.68–0.89× its time (only3d's estimates run
  0.75–0.89× Bambu's without supports too). A 200 mm table 100 mm up slices in 9 s against
  Bambu's 4 minutes.
- Fuzzy skin, classic noise (`FuzzySkin.cpp` `fuzzy_polyline` and `should_fuzzify`): the
  none / external / all / allwalls modes, thickness, point distance and first layer, read
  from and written to Bambu presets. A seeded generator keeps slices reproducible. On a
  pot it matches Bambu Studio 2.09 within 0.2 g and 2% of the time, with the same jitter
  (±0.19 mm standard deviation) and point spacing (0.84 against 0.86 mm). The perlin,
  billow, ridged and voronoi noises and the extrusion-width mode are not done.

Quick wins:
- Ironing to Bambu's 0.15 mm spacing / 10% flow / 30 mm/s.
- Calibration tools: flow, pressure advance, temperature and volumetric-speed towers
  (`Calib.cpp`), as a `calib_generate` / `calib_record` pair tied to the spool database.
- Orca's polyholes.
